# 真信盾安全设计

## 已实施控制

- 密码使用 Argon2 摘要保存，JWT 使用服务端密钥签发。
- Token 包含认证版本；修改密码后旧 Token 和推送设备可失效。
- 风险事件按用户隔离，家庭资源操作验证成员身份和角色。
- 密码重置码限时、限重发、限失败次数，并以摘要形式保存。
- 上传文件限制大小、类型和语音时长，临时文件在处理后清理。
- `.env`、私钥、Firebase 配置、服务账号和本地模型均被 Git 忽略。
- 风险提示避免“绝对安全”或“百分之百诈骗”等确定性措辞。
- 号码举报不保存原始号码，只保存基于服务端密钥的 HMAC 指纹和脱敏值；待复核举报不会直接影响自动拦截。

## 部署要求

1. 使用高熵 `JWT_SECRET_KEY`，生产环境通过密钥管理服务注入。
2. API 只通过 HTTPS 暴露，数据库、Redis、MinIO 不直接暴露公网。
3. 将 CORS 来源限制为实际客户端或管理端域名。
4. Firebase、SMTP 和 AI 服务凭证执行最小权限与定期轮换。
5. 日志不得包含密码、Token、验证码、完整聊天原文或完整联系方式。
6. 为登录、密码重置、上传、分析和通知接口增加网关级限流。
7. 配置数据库备份、恢复演练、迁移回滚方案和审计日志留存周期。

## 上线前缺口

- 当前应用内没有完整的分布式限流和审计日志平台。
- Redis 和 MinIO 已在基础设施中，但并非所有预期能力均已接入。
- 需要对依赖、镜像、Android 包和密钥泄漏执行自动扫描。
- 需要在真实 PostgreSQL、HTTPS 反向代理和生产通知渠道上做集成测试。
